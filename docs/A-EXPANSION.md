# A 第二轮完善：额度、历史、三个议题

更新日期：2026-09-09。三项功能不依赖团队 Access Secret 即可演示与验证。

## 如何演示

1. 首页选择 AI 编程、远程办公或 AI 作业，主按钮进入对应快照。
2. 在总览切换角度/立场、查看来源，进入讨论与圆桌。
3. 圆桌查看完整讨论，从待解问题进入对应分类补充材料。
4. 点“问题现场”仍回到当前议题；点“最近分析”可打开之前看过的结果。
5. 关闭标签页，同一浏览器再次打开网站，历史仍在；另一浏览器的访客看不到这份历史。

三个预置分析 ID：`demo-v1`、`demo-remote-work-v1`、`demo-ai-homework-v1`。议题 ID 为 `ai-coding`、`remote-work`、`ai-homework`。预置内容、作者与圆桌均为明确标注的模拟样本，不代表真实知乎原文。另两个议题各有 6 条主来源、2 条评论、6 个分类和 8 条圆桌发言。

## 调用次数保护

| 服务端环境变量                    | 默认 | 允许范围 | 含义                           |
| --------------------------------- | ---- | -------- | ------------------------------ |
| `ZHIHU_DAILY_CALL_LIMIT`          | 120  | 0–10000  | 全站每天最多准入的上游请求尝试 |
| `ZHIHU_VISITOR_DAILY_CALL_LIMIT`  | 20   | 0–1000   | 每个访客每天最多尝试次数       |
| `ZHIHU_VISITOR_MINUTE_CALL_LIMIT` | 6    | 0–60     | 每个访客过去 60 秒最多尝试次数 |
| `ZHIHU_MAX_CONCURRENT_CALLS`      | 2    | 0–8      | 全站同时执行的请求数           |

按北京时间换日；0 会阻止对应实时调用。空值使用默认，非法值阻止调用并提示配置有误。运行 `pnpm check:config` 可检查，不会访问知乎。开发配置放在 `.env.local` 后重启；生产从服务端环境变量注入。

这些值是应用保护，不是知乎官方余额，也不是费用预测。一次新分析通常消耗搜索和分类两个请求；首次实时圆桌、追问各再一次。缓存命中、预置、被限额拒绝的请求不计数；已准入后失败或结果不确定仍保留次数，不自动重试。

SQLite 单条条件插入控制并发准入。正常请求结束释放并发名额，进程中断时 70 秒租约过期释放。相同分析的圆桌生成另有操作锁。同一采集范围只允许一个进行中任务：本人复用任务，其他访客收到 `TOPIC_BUSY` 后可稍后取成功缓存。缓存有效期 1 小时，不向他人暴露任务 ID。

材料长度限制：主来源 2000 字符、评论 400 字符、每主来源最多 2 条评论、总材料 24000 字符。主来源优先，被截取处会在来源弹层提示。提示词加序列化输入超过 60000 字符时不调用模型。

## 历史的范围

`analysis_visits` 关联访客与结果，记录最近查看时间。`GET /api/history` 返回最近 20 个结果和最近 20 个任务；进行中/失败任务可从入口继续查询。查看、预置开启、成功采集与缓存命中都会记录结果。迁移还会回填旧版成功采集任务。

身份由 HttpOnly Cookie 持有；关闭标签页不会删除身份，清除 Cookie、身份过期或换浏览器后不能自动恢复。没有跨设备账号同步，也无法回填旧版未记录的预置浏览行为。历史只是私人入口，讨论区内容仍按产品设计共享。

## 给队友的接手点

- A：`budget.ts`、`jobs.ts`、`history.ts`、入口恢复及部署变量。
- B：`shared/topics.ts` 统一注册议题；实时构建必须传递 `topicId` 和服务端 `visitorId`；分类协议改变时同步 jobs 的 `DATA_VERSION`。
- C：拉取后执行 `pnpm db:migrate`；旧帖子、回复与点赞数据保留。
- D：`makePresetRound` 提供新议题的脚本；实时调用必须继续走 `generateJson` 的访客额度和相同材料生成锁。

新增迁移 `0003_ambitious_eternity.sql`；不要修改已部署迁移。额度不是排队器：被拒绝的请求不会后台等待。当前任务仍由 HTTP 请求承载，尚未接入持久队列，不能承诺关页后继续生成。

## 验收

- `pnpm test:entry`：隔离 SQLite，三议题/历史隔离、旧数据迁移、全站/个人次数、北京时间换日、并发抢占与过期锁、失败计数、输入长度、真实调用适配层的访客归属。测试使用人工响应，真实知乎网络请求为 0。
- `pnpm test:contracts`：来源引用、分类统计、圆桌回应与结构契约。
- `pnpm test:smoke`：本地四页、讨论发布回复点赞、圆桌隔离与补充持久化。
- `scripts/topic-checks.mjs`：隔离 Playwright page，检查三议题完整导航、圆桌到讨论、关闭标签页后的历史与移动宽度。
- `scripts/entry-checks.mjs`、`scripts/navigation-checks.mjs`：入口错误/恢复以及原四页交互回归。

真实知乎权限、相关性、生成质量、响应耗时与官方额度仍等待 Access Secret 后验收。
