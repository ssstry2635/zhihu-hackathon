# 知乎接口接入说明

依据：随工程保存的官方 `zhihu` skill 0.5.3-beta.20260904115023。入口为 [zhihu-skill/SKILL.md](zhihu-skill/SKILL.md)，HTTP 协议见 [http-api.md](zhihu-skill/references/http-api.md)。

## 认证

服务端使用 Bearer Access Secret，同时发送秒级 Unix 时间戳 `X-Request-Timestamp`。不要将 Access Secret 当作 OAuth App Key 或用户 access token。不要把它贴进代码、浏览器配置、文档、截图或日志。

本地开发可复制 `.env.example` 为被 Git 忽略的 `.env.local`，填写凭证并重启开发服务；也可在启动进程的受控环境中注入 `ZHIHU_ACCESS_SECRET`，然后启动 `pnpm dev`。工程启动配置只向服务端 Worker 注入该值，不使用 `VITE_` 或 `NEXT_PUBLIC_` 前缀。关闭终端或明确移除该进程环境后不再持有值。生产使用部署平台的加密凭证配置。

模型变量 `ZHIHU_MODEL` 可为 `zhida-fast-1p5` 或 `zhida-thinking-1p5`，以团队实际权限为准。没有设置时使用快速模型。

## 真实链路

1. 问题现场检测服务端 `/api/config` 的配置状态，不返回凭证，不将“已配置”视为“已验证”。
2. 用户点击“使用知乎实时采集”，创建持久化任务并执行；服务端报告真实阶段。相同范围 1 小时内复用已完成的快照。
3. 搜索返回最多10个结果；过滤问题条目和空摘要，按类型+内容 ID 去重。
4. 精选评论附着父来源，缺少作者时保持未知，不继承回答作者。
5. 分类生成仅使用当前样本；服务端核对引用原句与来源 ID，再计算数量和比例。
6. 结果存为固定快照。进入圆桌时使用同一份快照，结果按材料缓存。
7. 每名访客有独立圆桌会话和一次追问，补充帖子在共享讨论区中可见。

不会通过关键词改写伪造分页，不保证全部结果属于当前问题。实时失败不会静默切换另一套议题样本。

## 凭证到位后要做的验证

- 一次搜索：记录实际 `ContentType` 枚举、摘要长度、链接和评论覆盖情况。
- 一次分类：检查相关性、立场是否被简化、引用是否确实支持结论。
- 一次圆桌：检查上下文是否生效、交锋是否回答对方、没有把脚本共同点说成作者共识。
- 检查实际可用模型、请求耗时和额度；不要把官方默认试用额度当作团队比赛额度。
- 失败时停止无意义重试；未得到确定结果的模型 POST 不自动重复发送。

当前状态：适配层与团队凭证本地配置均已完成。2026-09-11 已用非预置问题验证搜索、分类、来源快照、实时角色生成与首轮自主发言；凭证未写入仓库。生产部署仍需单独注入密钥并复验。

## CLI

官方 CLI 不属于前端运行依赖。若开发者需要安装或升级，应遵循官方 skill 的授权及校验流程；不要调用来源不明的同名二进制。没有 CLI 也可按本文件开发和运行应用。

任务执行、缓存、断线恢复与 202 接口的完整契约见 [A-HANDOFF.md](A-HANDOFF.md)。执行请求需要保持连接；当前没有持久后台队列。

## 请求次数与材料长度保护

搜索、分类、实时圆桌、追问统一经过 `lib/server/budget.ts` 的原子准入计数。默认全站每天 120 次、单访客每天 20 次、每分钟 6 次、同时 2 次；按北京时间换日。这是应用设置，不是官方余额查询。缓存与预置不消耗，失败或结果不确定的已准入尝试也计数，不自动退还或重试。具体环境变量与边界见 [A-EXPANSION.md](A-EXPANSION.md)。

主来源最多 2000 字符，精选评论最多 400 字符且每主来源最多 2 条，总材料最多 24000 字符，先保留主来源，再补评论。被截取的来源保留 `truncated` 标记并在来源弹层提示。生成请求的提示词与序列化材料合计超过 60000 字符时拒绝调用。这些是字符限制，不能等同模型 token 数或确定费用。
