# 交付说明

## 现在能完整演示什么

1. 输入任意知乎问题标题，可选填原问题链接。
2. 服务端用多组查询变体（默认 4 轮、每轮 10 条）检索，按内容 ID 与规范化 URL 去重后保留最多 30 条唯一回答或文章摘要及精选评论。
3. AI 按讨论角度和观点立场分类；来源数量、比例和引用由服务端重新核对。
4. 用户进入分类讨论区，发布、回复、点赞并补充圆桌提出的待解问题。
5. 实时 Agent 按分类材料生成姓名与知识库，向主持人申请发言；主持人安排陈述、交锋和总结。
6. 任务、快照、帖子、圆桌与最近记录写入 D1，刷新后可继续。

## 本地交付验收

```sh
pnpm install
pnpm check:config
pnpm db:migrate
pnpm typecheck
pnpm test:contracts
pnpm test:entry
pnpm build
pnpm dev
```

服务启动后再运行 `pnpm test:smoke`。随后人工完成一次：自由标题采集 → 分类讨论 → 实时圆桌 → 主持人总结 → 把待解问题带回讨论区。

## 生产上线前

- 应用 `drizzle/` 中全部 D1 迁移，不能改写已发布迁移。
- 在托管平台加密配置 `ZHIHU_ACCESS_SECRET`，不要使用公开前缀，也不要提交 `.env.local`。
- 按实际额度设置 `ZHIHU_*_LIMIT` 四个保护变量。
- 部署后检查 `/api/config` 只返回配置状态，不返回密钥。
- 用一个新的非预置标题跑通真实采集和至少一轮圆桌。
- 检查站点访问权限，确保评委可直接打开。

## 必须对评委说清楚的边界

- 官方搜索返回的是相关样本，不是某问题下全部回答或全部评论。
- 原问题链接只用于溯源和返回知乎，不会绕过官方接口抓取页面。
- 分类可能重叠，所以比例不一定合计为 100%。
- “共同点”表示当前材料中的重合表述，不代表所有作者已经达成共识。
- 当前身份是演示访客 Cookie，不是知乎账号；浏览器扩展安装和 OAuth 不在本版 PRD 范围内。

## 故障时的可交付替代

- 缺少凭证或官方服务异常：进入三个预置议题，真人讨论功能仍可使用。
- 实时任务连接中断：从“最近分析”恢复任务，不自动重复消耗模型额度。
- 圆桌触发限流：已生成发言保留，稍后点击“继续调度”。
- 自由标题无有效结果：换成更完整的知乎问题标题；不要伪造分页或补入无来源内容。
